## Directory Purposes

**dot/ (CLI Tool):**
- Purpose: TypeScript/Bun command-line tool managing dotfile symlinks
- Contains: Main logic, tests, build output, dependencies
- Key files: `dot/index.ts` (entire CLI implementation), `dot/tests/` (comprehensive test suite)
- Built into: `dot/dot` binary deployed to `~/.local/bin/dot`

**zsh/ (Shell Configuration):**
- Purpose: Zsh interactive shell and login session configuration
- Contains: Init files (zshenv, zprofile, zshrc), modular config files, plugin scripts
- Organization: Files load in order (zshenv → zprofile → zshrc), then zshrc sources config/ and plugins/
- Symlinked to: `~/.zshenv`, `~/.config/zsh/.zprofile`, `~/.config/zsh/.zshrc`

**git/, tmux/, vscode/, jj/, iterm2/:**
- Purpose: Configuration for individual tools
- Each directory: Single tool's config file(s)
- Pattern: Simple structure, minimal nesting

**homebrew/:**
- Purpose: Track installed packages
- Contains: `brewfile` generated by `dot sync` from current Homebrew state
- Updated by: `dot sync` command (runs `brew bundle dump`, filters, writes)

**public-keys/:**
- Purpose: GPG public keys for reference
- Contains: .asc files for GPG identities
- Not managed by symlink system (informational only)

**~/.planning/codebase/:**
- Purpose: Documentation for orchestrator and future Claude instances
- Contains: Architecture docs, structure docs, testing patterns, conventions
- Not part of dotfiles (generated by planning system)

## Naming Conventions

**Files:**
- Main source: `index.ts` (single module contains entire CLI)
- Tests: `*.test.ts` (co-located in `tests/` directory)
- Config: `*rc` files (zshrc, zprofile, .gitconfig, tmux.conf)
- TOML configs: `config.toml` (starship.toml, jj/config.toml)
- JSON configs: `settings.json` (vscode), profile JSON (iterm2)

**Directories:**
- Shell config organization: `config/` (loaded files), `plugins/` (plugin files)
- Tests: `tests/` directory at module root
- Symlink targets: `~/.config/<tool>/` (standard XDG directory)

**Functions:**
- Command handlers: Action verbs (install, uninstall, sync, doctor, review)
- Async operations: async/await pattern throughout
- Getters: get* prefix (getSymlinkStatus, getRepoFiles, getDotfiles, getGitStatus)
- Helpers: Descriptive names (resolveSymlinkTarget, linksToExpectedResolved, pathExists)
- Filters: filter* prefix (filterBrewfile)

**Types:**
- Pascal case (Config, SymlinkStatus, Dotfile, ReviewedPaths)
- Exported from functions that return them

## Where to Add New Code

**New Symlink Target:**
1. Add config file to appropriate directory (e.g., `nvim/init.lua` for Neovim)
2. Add entry to `LINKS` record in `dot/index.ts` lines 37-46
3. Update README.md symlink table
4. Rebuild: `cd dot && bun run deploy`
5. Run: `dot install`

**New Command:**
1. Create async function in `dot/index.ts` (before CLI router)
2. Add case to switch statement in lines 578-597
3. Export function if it needs testing
4. Add to help() function output
5. Write tests in appropriate `dot/tests/*.test.ts` file

**New Zsh Config:**
1. For aliases/functions: Add to `zsh/config/aliases.zsh`
2. For settings: Add to `zsh/config/options.zsh`
3. For completions: Add to `zsh/config/completions.zsh`
4. For colors: Add to `zsh/config/colors.zsh`
5. Files auto-sourced by zshrc (lines source config/*.zsh)

**New Zsh Plugin:**
1. Create `zsh/plugins/myplugin.zsh`
2. File auto-sourced by zshrc (lines source plugins/*.zsh)
3. Document in `zsh/README.md` plugins table

**Utilities:**
- Shared TypeScript helpers: Add to `dot/index.ts` before CLI router
- Zsh helpers: Add to appropriate `zsh/config/*.zsh` file
- Export from `dot/index.ts` if used in tests

**Tests:**
- Unit tests for pure functions: `dot/tests/index.test.ts`
- Integration tests with I/O: `dot/tests/integration.test.ts`
- Git/file persistence tests: `dot/tests/doctor.test.ts`
- Pattern: describe/test blocks with beforeEach/afterEach setup/teardown

## Special Directories

**.planning/codebase/ (Planning Directory):**
- Purpose: Architecture and quality documentation
- Generated: Auto-created by planning orchestrator
- Committed: No, these are analysis documents
- Use: Reference for orchestrator phases (holds ARCHITECTURE.md, STRUCTURE.md, etc.)

**.dotfiles/ (Repository Root):**
- Purpose: Repo root marker
- Generated: No
- Committed: Yes (defined in LINKS as symlink target)

**dot/ (CLI Subdirectory):**
- Purpose: Isolated TypeScript/Bun project
- Generated: `node_modules/`, `dot/dot` binary
- Committed: No (gitignore excludes generated files)
- Note: `bun.lock` committed for reproducibility

**zsh/config/ and zsh/plugins/:**
- Purpose: Modular shell configuration
- Generated: No
- Committed: Yes, all configuration files
- Auto-loaded: zshrc sources these with `source $ZDOTDIR/config/*.zsh` and similar

**~/.config/zsh/, ~/.config/git/, etc. (Symlink Targets):**
- Purpose: System configuration directories (not in repo)
- Generated: Via symlinks created by `dot install`
- Committed: No (outside repository)
- Contents: Symlinks pointing to `~/.dotfiles/` equivalents
