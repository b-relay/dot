# Phase 8.1: Symlink Path Fix

## Issue

**Critical Bug**: `installLinks()` in `src/init.ts` doesn't expand `~` to home directory.

The config stores paths like `~/.config/zsh/.zshrc` for portability. But `installLinks()` passes these directly to `mkdir()` and `symlink()`, creating a literal `~/` folder inside the dotfiles repo instead of expanding to the actual home directory.

## Root Cause

```typescript
// src/init.ts line 155-187
async function installLinks(links: LinkMap): Promise<void> {
  for (const [source, target] of Object.entries(links)) {
    await mkdir(dirname(target), { recursive: true });  // Creates ~/... literally!
    await symlink(source, target);  // Creates symlink at ~/... literally!
  }
}
```

The main `index.ts` has `createConfig()` which properly expands `~`:
```typescript
const resolvedTarget = target.startsWith("~/")
  ? resolve(resolvedHome, target.slice(2))
  : target.startsWith("~")
    ? resolvedHome
    : target;
```

But `init.ts` has its own `installLinks()` that lacks this expansion.

## Fix

Add path expansion helper and use it in `installLinks()`:

```typescript
function expandTilde(path: string): string {
  const home = process.env.HOME;
  if (!home) throw new Error("HOME environment variable not set");
  if (path === '~') return home;
  if (path.startsWith('~/')) return resolve(home, path.slice(2));
  return path;
}

async function installLinks(links: LinkMap): Promise<void> {
  for (const [source, target] of Object.entries(links)) {
    const expandedTarget = expandTilde(target);
    await mkdir(dirname(expandedTarget), { recursive: true });
    await symlink(source, expandedTarget);
    ...
  }
}
```
